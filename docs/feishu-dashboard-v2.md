# 飞书官网运营看板 V2

## 目标

看板面向不熟悉 GA4、GSC 和数据库字段的运营人员。页面只回答三个问题：

1. 本周官网结果怎样？
2. 与前几周相比发生了什么变化？
3. 流量来自产品页还是信息页，哪个产品大类需要采取行动？

核心数据模型是“页面类型 × 产品大类 × 周期”。页面类型由官网数据库的 URL 路由和模板维表确定，产品大类只对已确认的产品页生效。GA4、GSC、官网询盘数据库是三个独立事实来源，只做并列观察，不拼成严格转化漏斗。

## 飞书入口

- Base：<https://genemedi.feishu.cn/base/Qk54bBp6Zacl8BsIK07cUrWange>
- `官网运营驾驶舱`：面向负责人，展示本周结果与近 4 周变化。
- `产品趋势与行动`：面向运营，按 GMP 系列、SOLIDEX / ISOEx、AAV 纯化与滴度比较产品表现。

旧的 `运营总览` 和 `产品与 SEO` 已删除。

## 指标口径

| 看板名称 | 数据源 | 业务含义 |
| --- | --- | --- |
| 官网访问次数 | GA4 `sessions` | 用户进入官网形成的访问会话数 |
| 官网访客数 | GA4 `activeUsers` | 在周期内有互动的用户数 |
| 表单提交事件（GA4） | GA4 `keyEvents` | GA4 记录到的表单提交关键事件，不等同于数据库询盘 |
| Google 自然搜索点击 | GSC `clicks` | 从 Google 自然搜索结果进入官网的点击数 |
| Google 搜索曝光 | GSC `impressions` | 官网页面在 Google 搜索结果中出现的次数 |
| 搜索点击率 | GSC `ctr` | 自然搜索点击数除以曝光数 |
| 平均搜索排名 | GSC `position` | 搜索结果平均位置，数值越小通常越靠前 |
| 表单入库总数 | 官网数据库 `storedSubmissions` | 数据库实际保存的全部表单记录 |
| 官网入库询盘 | 官网数据库 `nonQuarantinedSubmissions` | 未进入 `SPAM_QUARANTINE` 的记录；不是销售已确认的合格线索数 |
| 产品页访问次数 | GA4 页面明细 + 页面维表 | 数据库模板确认的产品页会话数 |
| 信息页访问次数 | GA4 页面明细 + 页面维表 | 数据库模板确认的信息页会话数 |
| 页面访问分类覆盖率 | GA4 页面明细 + 页面维表 | 已确认为产品页或信息页的页面会话，占全部可见页面明细会话的比例 |

GA4 周总数必须使用区间聚合结果，不使用每日明细求和替代。不同数据源的时区和去重规则不同，因此关键事件与数据库询盘不要求相等。

## 数据完整性

- GA4、GSC 和询盘缺一项时，周期标为 `partial`，不能把缺失值写成 `0`。
- `dbname=pages` 必须按模板规则分类；动态路由只接受页面分类 YAML 中已审核的 `urltable.dbname` 或固定运行时路径规则，不能按 `/i/` 前缀猜测。
- 产品大类汇总只接受 `product_page`；信息页、技术页、未分类页、异常页和 PDF 不进入产品大类。
- 当前看板有 4 周 GA4/GSC 数据。
- 询盘数据只有最近 2 周完整；更早 2 周保持为空，并在看板说明中明确提示。

## 本地维护文件

- `config/feishu_dashboard/v2/dashboard_manifest.json`：两个看板及图块定义。
- `config/feishu_dashboard/v2/text_block_registry.json`：飞书原生富文本组件登记表。文本正文由飞书 UI 维护，避免 lark-cli 1.0.65 将换行和引号重复转义。
- `config/feishu_dashboard/v2/field_updates.json`：字段中文化配置。
- `config/feishu_dashboard/v2/field_creates.json`：新增对比和运营提示字段。
- `scripts/build_feishu_dashboard_v2_payloads.py`：从已脱敏本地缓存生成周数据。
- `scripts/apply_feishu_dashboard_v2_schema.py`：预览或应用字段变更。
- `scripts/apply_feishu_dashboard_v2_records.py`：预览或写入周数据。
- `scripts/apply_feishu_dashboard_v2_dashboards.py`：预览或创建看板。
- `scripts/verify_feishu_dashboard_v2.py`：从飞书读回图表数据并验收。

所有写入脚本默认只做 dry-run，必须显式传入 `--apply` 才会修改飞书。

## 服务器定时同步

- 增量任务在上海时区的 01、03、05、07、09、13、15、17、19、21、23 点 15 分运行，并带 0 至 5 分钟随机延迟；更新近期日、周、月和滚动周期。
- 完整回补任务每天 11 点 15 分运行，并带 0 至 5 分钟随机延迟；用于补齐保留范围内的历史周期。
- 两个任务都使用稳定周期键执行幂等 upsert，不会因重复运行产生重复周期。
- 服务器保持关闭全局 TUN。分析同步服务通过进程级环境变量让 GA4、GSC 和飞书请求显式使用本机 `8890` 代理；官网询盘数据库通过 `NO_PROXY` 保持直连，因此不会接管其他项目的默认网络。
- GSC 使用的 `httplib2` 必须安装项目声明的 `PySocks` 依赖，否则 HTTPS 代理不会生效并会退回直连。部署后应确认 GSC 连接指向 `127.0.0.1:8890`，而不是公网 Google IP。
- 任务失败时保留上次成功数据，不会用 `0` 覆盖缺失来源；飞书的连接重置、超时、429 和 5xx 会做有限次退避重试。

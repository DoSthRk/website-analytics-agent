# 官网分析可扩展时间模型

## 设计结论

统计模型从“固定周报”升级为“精确区间快照”。每一条记录仍然遵循两个核心维度：

- 时间：日、周、月、季度、年度、滚动窗口或自定义日期范围。
- 产品：以审核后的三级产品层级为稳定维度，包括 TARMART、Gene Therapy、Diagnostics、Biologics、Immunology & Cell Therapy 及补充分组。

同一日期范围可以存在不同统计粒度，例如“2026-08-10 至 2026-08-16（周）”和“滚动7天”。它们使用不同周期键，避免覆盖。

## 为什么不能只保存日数据再求和

GA4的区间访问和访客指标必须由GA4对完整区间聚合。特别是活跃用户是区间去重指标，不能把每天的活跃用户相加；实践中GA4区间会话汇总也可能与每日行求和存在差异。

因此：

- 日数据用于观察日趋势。
- 周、月、季度、年度和滚动窗口都单独请求对应区间。
- 看板指标卡使用区间快照，不能从日趋势图反推总数。

## 周期键

```text
站点|统计类型|开始日期|结束日期
```

示例：

```text
genemedi-net|week|2026-08-10|2026-08-16
genemedi-net|rolling-7d|2026-08-10|2026-08-16
genemedi-net|month|2026-08-01|2026-08-31
genemedi-net|custom|2026-08-10|2026-08-16
```

产品记录在周期键后追加稳定的产品大类ID。同步程序必须按该键执行upsert，不能在每次运行时重复新增记录。

页面类型是独立维度。GA4 总量、每日和页面请求先按注册域名精确过滤 `hostName`；GA4、GSC和询盘的页面URL再统一为规范路径。`dbname=pages` 的路由严格依据 `pages.template` 是否包含 `sideba` 分类；官网运行时已经确认的动态 `urltable.dbname` 使用版本化渲染器规则；`/g/`、文章和技术端点使用固定路径规则。未审核来源和冲突路由不得按URL名称猜测。只有 `product_page` 可进入产品三级分类；`information_page` 使用“业务主题 + 内容类型”两个辅助维度；`technical_page`、`unknown_unmapped`、`invalid_broken` 和 `pdf_asset` 保持独立状态。每次同步记录页面分类版本、产品映射版本、信息页映射版本和按来源计算的分类覆盖率。

核心运营分析仍然是“产品 × 时间”。一级、二级、三级产品分类用于按不同颗粒度横向比较；信息页的主题和内容类型用于解释流量来源，不与产品分类混为同一字段。

## 数据新鲜度

一个周期有“目标结束日期”，每个来源另有自己的“数据截至日期”：

- `GA4数据截至`
- `GSC数据截至`
- `询盘数据截至`

周期状态：

- `complete`：全部来源覆盖到周期结束日期。
- `preliminary`：来源连接正常，但至少一个来源尚未覆盖到周期结束日期。
- `partial`：来源失败、被截断或缺失，不能把缺失指标写成0。

`是否最终值`只在周期为`complete`时勾选。当前周期通常为`preliminary`，历史周期在后续回补后升级为`complete`。

## 默认同步范围

`config/sync_profiles/genemedi-net.json`定义首版范围：

- 最近14个日周期
- 最近12个周周期
- 最近12个月周期
- 最近8个季度
- 最近3个年度
- 滚动7天、28天和90天

这些是自动物化范围，不限制Agent临时查询任意自定义日期。自定义日期只在用户明确提出时拉取和保存。

## 飞书模型迁移

V2 的`全站周数据`和`产品周数据`继续保留为只读回退。V3 已新增：

- `全站每日数据`：站点 × 数据日期。
- `产品每日数据`：站点 × 数据日期 × 产品末级分类。
- `信息页每日数据`：站点 × 数据日期 × 信息主题 × 内容类型。

三个 V3 看板分别是`负责人驾驶舱 V3`、`产品表现 V3`和`内容与 SEO V3`。每个看板都有`数据日期`全局筛选，默认显示过去 30 个自然日；运营人员可改为过去 7 天、本月、上月、单日或自定义起止日期。图表同时固定筛选`数据状态 = 完整`，失败、截断或尚未最终化的来源不会被写成 0。

V3 为了支持交互式任意日期，指标卡对每日可加指标求和。`GA4 active users`、GSC 日点击率、GSC 日平均排名和每日页面数等不可直接跨日相加的指标不进入默认看板。若需要与 GA4 界面严格一致的区间去重用户数或其他非可加指标，Agent 必须对完整区间重新调用来源 API，不能从每日表反推。

V3 写入按稳定键补缺失记录，不删除旧记录；回填前必须通过本地 reconciliation，写入后再回读全部键、日期、单元格和加总指标。飞书目标表和看板 ID 记录在`config/feishu_dashboard/v3/`，敏感凭据仍不进入仓库。

## Agent和定时程序的分工

- 定时程序负责固定、可审计、可重试的数据拉取和飞书upsert。
- Agent负责理解自然语言，生成临时自定义区间、解释变化和提出运营建议。
- GA4、GSC和官网询盘继续保持独立事实来源；任何一个来源失败都不能伪装成完整报告。

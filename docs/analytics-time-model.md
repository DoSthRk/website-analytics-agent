# 官网分析可扩展时间模型

## 设计结论

统计模型从“固定周报”升级为“精确区间快照”。每一条记录仍然遵循两个核心维度：

- 时间：日、周、月、季度、年度、滚动窗口或自定义日期范围。
- 产品：全站、GMP、SOLIDEX、AAV Processing，以及未来审核通过的新大类。

同一日期范围可以存在不同统计粒度，例如“2026-08-10 至 2026-08-16（周）”和“滚动7天”。它们使用不同周期键，避免覆盖。

## 为什么不能只保存日数据再求和

GA4的区间访问和访客指标必须由GA4对完整区间聚合。特别是活跃用户是区间去重指标，不能把每天的活跃用户相加；实践中GA4区间会话汇总也可能与每日行求和存在差异。

因此：

- 日数据用于观察日趋势。
- 周、月、季度、年度和滚动窗口都单独请求对应区间。
- 看板指标卡使用区间快照，不能从日趋势图反推总数。

## 周期键

```text
站点|统计类型|开始日期|结束日期
```

示例：

```text
genemedi-net|week|2026-08-10|2026-08-16
genemedi-net|rolling-7d|2026-08-10|2026-08-16
genemedi-net|month|2026-08-01|2026-08-31
genemedi-net|custom|2026-08-10|2026-08-16
```

产品记录在周期键后追加稳定的产品大类ID。同步程序必须按该键执行upsert，不能在每次运行时重复新增记录。

页面类型是独立维度。GA4 总量、每日和页面请求先按注册域名精确过滤 `hostName`；GA4、GSC和询盘的页面URL再统一为规范路径。`dbname=pages` 的路由严格依据 `pages.template` 是否包含 `sideba` 分类；官网运行时已经确认的动态 `urltable.dbname` 使用版本化渲染器规则；`/g/`、文章和技术端点使用固定路径规则。未审核来源和冲突路由不得按URL名称猜测。只有 `product_page` 可进入产品大类；`information_page`、`technical_page`、`unknown_unmapped`、`invalid_broken` 和 `pdf_asset` 保持独立状态。每次同步记录页面分类版本和按来源计算的分类覆盖率。

## 数据新鲜度

一个周期有“目标结束日期”，每个来源另有自己的“数据截至日期”：

- `GA4数据截至`
- `GSC数据截至`
- `询盘数据截至`

周期状态：

- `complete`：全部来源覆盖到周期结束日期。
- `preliminary`：来源连接正常，但至少一个来源尚未覆盖到周期结束日期。
- `partial`：来源失败、被截断或缺失，不能把缺失指标写成0。

`是否最终值`只在周期为`complete`时勾选。当前周期通常为`preliminary`，历史周期在后续回补后升级为`complete`。

## 默认同步范围

`config/sync_profiles/genemedi-net.json`定义首版范围：

- 最近14个日周期
- 最近12个周周期
- 最近12个月周期
- 最近8个季度
- 最近3个年度
- 滚动7天、28天和90天

这些是自动物化范围，不限制Agent临时查询任意自定义日期。自定义日期只在用户明确提出时拉取和保存。

## 飞书模型迁移

当前表名仍为`全站周数据`和`产品周数据`。正式启用同步时将改为：

- `全站周期数据`
- `产品周期数据`

新增字段包括统计粒度、滚动天数、三个来源的数据截至日期、是否最终值、看板窗口和同步批次。`看板窗口`用于让现有图表稳定筛选“当前周期”“近4周”“近12周”或“近12个月”，历史记录不会删除。

## Agent和定时程序的分工

- 定时程序负责固定、可审计、可重试的数据拉取和飞书upsert。
- Agent负责理解自然语言，生成临时自定义区间、解释变化和提出运营建议。
- GA4、GSC和官网询盘继续保持独立事实来源；任何一个来源失败都不能伪装成完整报告。

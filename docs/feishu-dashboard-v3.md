# 飞书官网运营看板 V3 设计稿

## 当前状态

V3 是本地 dry-run 设计，`write_enabled=false`，尚未创建飞书表，也没有修改 V2 线上看板。V2 继续运行，直到 V3 每日数据回填、日期筛选和运营验收全部通过。

## 为什么改为每日数据

运营人员需要自己选择起止日期。周期预聚合记录会在日期范围筛选时发生重叠和重复汇总，因此 V3 只保存单日事实：

- `全站每日数据`：站点 × 数据日期。
- `产品每日数据`：站点 × 数据日期 × 产品末级分类。
- `信息页每日数据`：站点 × 数据日期 × 信息主题 × 内容类型。

飞书看板使用统一的 `数据日期` 范围筛选器。用户可以选择最近 7 日、最近 28 日、本月、上月，或自行输入起止日期。三个看板上的访问、搜索、曝光、事件和询盘均按筛选后的每日记录求和。

## 数据生成方式

每个数据日使用一次现有受限 CLI，令 `start=end=数据日期`。该方式复用已经审核过的 GA4 页面、GSC 页面和询盘页面查询，不新增任意 API 维度，也不接受 URL、SQL 或请求体。

只有 GA4、GSC 和官网数据库三类来源均达到最终状态的日期才进入 V3。按当前保守延迟，默认看板的数据截止日期由三类来源中最晚完成的一方决定，通常受 GSC 最终数据延迟约束。

`scripts/build_feishu_dashboard_v3_dry_run.py` 将单日 CLI 结果、受控缓存和同日页面维表转换为三张每日事实表。脚本只生成本地 JSON，不写飞书。

连续日期回填使用 `scripts/backfill_feishu_dashboard_v3.py`。它只读取受限 CLI 已生成的逐日脱敏缓存、审计清单和页面维表快照；任意一天不是三源完整、GSC 明细被截断、稳定键重复或分类汇总不平，整个批次都会失败，不产生可写飞书的结果。

```powershell
.\.venv\Scripts\python.exe scripts\backfill_feishu_dashboard_v3.py `
  --site genemedi-net `
  --start 2026-07-25 `
  --end 2026-08-21 `
  --cache-dir cache `
  --audit-dir audits `
  --page-dimension-fixture outputs\feishu-v3-backfill\source\page_dimension.json `
  --output outputs\feishu-v3-backfill\genemedi-net_2026-07-25_2026-08-21.json
```

该命令只生成本地 `backfill_dry_run` 文件，`write_enabled=false`，不会创建或更新飞书记录。

## 自定义日期下的指标规则

可以跨日求和并进入默认看板的指标：

- GA4 官网访问次数、GA4 表单提交事件。
- GSC 自然搜索点击、GSC 搜索曝光。
- 官网数据库表单入库总数、官网入库询盘。
- 产品页、信息页和其他页面访问次数。

以下指标不能直接跨日相加，因此不进入默认日期看板：

- GA4 访客数：每日去重访客相加不等于日期区间去重访客。
- GSC 点击率：必须用区间总点击除以区间总曝光，不能平均每日点击率。
- GSC 平均排名：需要按曝光加权，未验证飞书聚合公式前不展示区间值。
- 每日页面数：同一页面会跨日重复，只用于单日审计，不作为区间 KPI。

## 三个看板

- `负责人驾驶舱 V3`：访问、自然搜索点击、GA4 表单事件、官网入库询盘、每日趋势和页面类型构成。
- `产品表现 V3`：按一级、二级、三级产品分类筛选，在用户选择的日期范围内汇总访问、搜索、曝光和询盘。
- `内容与 SEO V3`：按信息主题和内容类型筛选，在用户选择的日期范围内汇总内容表现。

GA4、GSC 和官网数据库继续作为三套独立来源展示，不拼成严格转化漏斗。

## 幂等与总量校验

- 全站稳定键：`site|YYYY-MM-DD`。
- 产品稳定键：`site|YYYY-MM-DD|product_line_id`。
- 信息页稳定键：`site|YYYY-MM-DD|theme_id|content_type_id`。
- 产品表每天写入所有产品分类，包括零值行，避免数据修订后残留旧值。
- 信息页表每天写入全部“主题 × 内容类型”组合，包括零值行，避免数据修订后残留旧值。
- 每日产品汇总必须等于当日 `product_page` 总量。
- 每日信息页交叉汇总必须等于当日 `information_page` 总量。
- 全站的产品页、信息页和其他页面访问之和必须等于当日 GA4 Sessions。

## 上线顺序

1. 固化每日数据契约与日期筛选配置。
2. 使用受限 CLI 完成至少 28 个最终数据日的本地 dry-run 回填。
3. 核对每日稳定键、三源总量、页面类型总量、产品和信息页汇总。
4. 新建三张 V3 飞书表，不修改 V2。
5. 回填最多 400 个最终数据日，并创建三个带自定义日期筛选器的看板。
6. V2/V3 并行运行至少一个完整周；验收通过后再决定是否归档 V2。

## 验收条件

- 任意日期范围内不存在周、月、滚动窗口记录重复汇总。
- 起止日期均包含在结果内，三个看板使用同一个日期范围。
- 日期范围内的 GA4、GSC、询盘总量等于逐日受限 CLI 结果之和。
- 产品汇总只包含 `product_page`；信息页汇总只包含 `information_page`。
- 一级分类汇总等于其二级、三级明细之和。
- 信息主题与内容类型交叉汇总等于信息页总量。
- 未达到最终状态的日期不进入默认看板，缺失来源不写成零。
- 线上切换前保留 V2、旧表和回滚路径。

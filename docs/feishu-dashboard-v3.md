# 飞书官网运营看板 V3 设计稿

## 当前状态

V3 目前是本地 dry-run 设计，不包含飞书表 ID，也没有任何写入或部署动作。V2 线上看板继续运行，直到 V3 字段、示例数据和迁移方案全部审核通过。

本地 dry-run 由 `scripts/build_feishu_dashboard_v3_dry_run.py` 生成，仅读取受控 CLI 缓存和审核过的页面证据。输出文件固定标记 `write_enabled=false`。当前原型将产品页证据快照与信息页明确 slug 规则用于界面验证；未命中的页面保留为“其他”，正式同步前必须改用同周期 `pages.template` 页面维表重新生成。

2026-08-10 至 2026-08-16 的首次原型包含 2 条全站周期记录、22 条产品周期记录和 23 条信息页周期记录。该数量只用于验证字段、筛选器、汇总和阅读体验，不等同于线上最终分类覆盖率。

## 设计目标

V3 面向不熟悉 GA4、GSC 和数据库字段的运营人员。默认阅读顺序是：

1. 先看本期结果以及与上一期的变化。
2. 再区分流量来自产品页、信息页还是其他页面。
3. 产品页按一级、二级、三级产品分类下钻。
4. 信息页按“业务主题 + 内容类型”解释内容表现。

核心运营模型仍然是“产品 × 时间”。信息页维度用于解释获客内容，不与产品分类混成同一个字段。

## 三张事实表

### 全站周期数据

每个站点、每个统计周期一行。用于负责人驾驶舱，保留 GA4、GSC、官网数据库三套独立指标，以及产品页、信息页和其他页面的访问构成。

### 产品周期数据

每个周期、每个产品末级分类一行。一级、二级、三级分类全部作为独立字段保存，因此看板既可以汇总到大类，也可以下钻到具体产品分类。

### 信息页周期数据

每个周期、每个“信息主题 × 内容类型”组合一行。例如“基因治疗 × 实验方案与应用”。该交叉颗粒度可以同时回答内容在讲什么、页面承担什么任务。

## 三个看板

- `负责人驾驶舱 V3`：四张核心指标卡、全站趋势、产品页与信息页访问构成。
- `产品表现 V3`：三级分类筛选、产品访问/搜索/询盘排行和连续周期趋势。
- `内容与 SEO V3`：信息主题、内容类型、搜索曝光与点击机会清单。

## 运营判断规则

- 访问增长、搜索点击同步增长：记录为正向变化，继续观察连续周期。
- 搜索曝光较高、点击率较低：优先检查标题、摘要和搜索意图匹配度。
- 产品页访问较高、数据库询盘较低：检查行动按钮、表单路径和流量相关性，但不直接认定为页面故障。
- GA4 关键事件与数据库询盘差异较大：先检查两套口径和时间边界，不直接相减。
- `Other Product`、`GENERAL` 和 `GENERAL_INFORMATION` 是显式兜底分类，不等于页面身份未知。

## 迁移顺序

1. 固化 V3 数据契约与 dry-run 示例。
2. 在新表中创建字段，不修改 V2 表。
3. 回填 4 周历史并核对稳定键、总量和分类覆盖率。
4. 创建 V3 看板并由运营人员审核。
5. 并行运行 V2/V3 至少一个完整周。
6. 验收通过后再决定是否归档 V2。

## 验收条件

- 三张表均按稳定键幂等写入，无重复周期。
- 全站表的 GA4、GSC、询盘总量与受限 CLI 同周期结果一致。
- 产品汇总只包含 `product_page`；信息页汇总只包含 `information_page`。
- 一级分类汇总等于其二级、三级明细之和。
- 信息主题与内容类型交叉汇总等于信息页总量。
- `partial` 周期不得显示为完整数据，缺失来源不得写成零。
- 线上切换前保留 V2 与回滚路径。
